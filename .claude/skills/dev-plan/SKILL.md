`docs/DEV_PLAN.md`를 실제 코드 상태와 동기화한다.

## 절차

1. `docs/DEV_PLAN.md`를 Phase 0부터 순서대로 읽는다.
2. 각 미완료(`- [ ]`) 항목에 대해 관련 파일/코드/설정이 실제로 존재하고 요구사항을 충족하는지 확인한다.
   - 예: "POST /api/pots 구현"이 완료로 보이려면 해당 Route Handler가 실제로 DB에 쓰기 작업을 해야 한다. `lib/api.ts`가 여전히 `mock-data.ts`를 반환하고 있으면 미완료로 판정한다.
   - 예: "Vercel 첫 배포 실행"은 `vercel ls`로 최근 배포가 있는지 확인한다.
3. 완료로 확인된 항목은 Edit 도구로 `- [ ]`를 `- [x]`로 직접 바꾼다. 추측으로 체크하지 않는다 — 근거가 되는 파일/코드를 확인한 항목만 체크한다.
4. Phase 순서를 건너뛰고 뒤 Phase 작업이 앞 Phase보다 먼저 되어 있으면(의존성 위반) 사용자에게 알린다 — 예: 인증(Phase 2) 없이 참여 신청(Phase 4)이 동작하면 권한 검사 누락 위험이 있다.
5. 이번에 새로 체크된 항목, 여전히 막혀 있는 항목, 다음으로 착수해야 할 Phase를 요약해 보고한다.
